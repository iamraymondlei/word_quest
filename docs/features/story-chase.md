# Story Chase

## 1. 目的

Story Chase 是每个故事的第 2 关，内部模式值仍为 `listening`。学员使用电脑实体键盘逐字输入故事，在城堡追逐场景中控制 Buddy 前进并躲避怪兽，以速度、准确度和生命值获得反馈。

## 2. 设备边界

- 只支持电脑端；iPad/平板在地图入口和 `GamePlay` 根组件各有一道拦截。
- 依赖连续键盘输入、空格、退格和 Tab；不得仅靠隐藏入口实现设备限制。
- 触屏用户应被引导到 Reading & Typing 或 Word Matching。

## 3. 核心流程

1. 从故事正文/分段 JSON 生成可输入字符流，并按可配置的每页最大行数分页。
2. 首行加入四个空格的段落缩进；Tab 可补齐当前所需缩进。
3. 开局和切页先进入怪兽等待倒计时；倒计时结束后怪兽出现并追逐。
4. 正确字符推动 Buddy 前进；错误字符累积并影响生命/追逐距离。
5. 达到连续错误阈值时触发惩罚；完成页面后进入下一页。
6. 完成故事后更新关卡 2 位图，并按全局设置结算完成、速度及满生命金币奖励。

## 4. 可配置项

当前全局设置来自 `/api/game-settings`，包括：

- 慢/中/快怪兽速度；
- 怪兽等待秒数与答对后的退后距离；
- 连续错误上限、每页最大行数、初始生命；
- 完成、速度、满生命金币奖励；
- 怪兽池；
- AI 绘本导入提示词模板（与本关共享设置表，但不是追逐运行参数）。

键名及存储方式见 [../DATA_MODEL.md](../DATA_MODEL.md)，接口见 [../API.md](../API.md)。

## 5. 显示和无障碍要求

- 当前字符、正确/错误字符和焦点必须有不只依赖颜色的反馈。
- 动画不能阻止键盘输入；切页、暂停或失焦时应正确清理计时器。
- 怪兽冷却期间不渲染已进入跑道的怪兽，同时显示明确倒计时。
- 角色和怪兽资源的显示名称不应决定持久化合同；数据库保存稳定标识。
- `prefers-reduced-motion` 用户应得到可读、可操作的降级体验。

## 6. 测试重点

- 首行缩进、Tab、标点、空格、退格、超长输入和分页边界。
- 开局/切页倒计时只启动一次，计时器在卸载后不更新状态。
- 错误阈值、生命下限、怪兽距离及三种速度。
- 重复通关不重复增加完成星星；金币奖励规则符合设置。
- iPad 前置和游戏内拦截均不能绕过。
