# 测试策略

## 1. 目标

测试必须证明核心学习进度、故事管理、数据库迁移兼容和 AI CLI 解析不会破坏既有数据。任何自动化测试都只能使用专用测试数据库。

## 2. 现有测试

### Backend Jest

`backend/tests/` 当前覆盖：

- 数据库连接与自动迁移兼容；
- 故事分组 CRUD、保留名称和故事归组；
- 学员故事分配；
- 关卡进度、完成位图、星星和重算；
- 全局游戏设置；
- 词汇与相关接口。

Jest `globalSetup` 会创建/补齐 `TEST_DB_NAME` 指定的数据库及表。它当前会捕获初始化失败后继续，这可能造成误导，见 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)。

### AI service Pytest

`ai_agent/tests/` 覆盖自定义提示词传递及 CLI 执行/解析行为。测试应 mock 外部 CLI 或使用隔离配置，不能消费真实生产任务或改写个人 CLI 登录资料。

### Frontend

当前没有前端自动化测试框架；最低质量门槛是 TypeScript 与 Vite 生产构建。关键交互仍需手工验收。

## 3. 常规命令

```bash
cd backend
npm test
npm run build
```

```bash
cd frontend
npm run build
```

```bash
cd ai_agent
.venv/bin/python -m pytest
```

```bash
docker compose config
```

根目录没有统一 `npm test` 或一键质量脚本；必须在对应子项目运行。

## 4. 测试数据库规则

- `TEST_DB_NAME` 必须显式指向如 `wordquest_agent_test` 的专用库，且不得等于 `DB_NAME`。
- 运行测试前显示并人工核对主机、端口和库名，但日志不得显示密码。
- 测试可以重建或清理专用测试库中的数据；不得对开发或生产库执行清理。
- 测试用户、故事和词汇应使用唯一前缀，并由测试负责清理。
- 数据库不可用、初始化失败或 migration 失败时，测试套件必须失败，不得只打印警告。

## 5. 手工验收矩阵

| 范围 | 最低验收 |
|---|---|
| 档案 | 新建/再次登录不覆盖头像；管理员进入管理页；删除级联正确 |
| 故事 | 新建、更新、分组筛选、用户分配、无分配回退行为 |
| 关卡 | 四个关卡分别完成并写入正确位图；重复完成不重复加星 |
| 设备 | iPad 可用 01/03，不能进入 02/04；电脑四关可进入 |
| Speech | HTTPS 下授权、实时识别、结束诊断、无权限和不支持浏览器错误 |
| 内容导入 | CSV 错误提示；AI 工具/模型选择；1/10/11 张图片边界；失败不写半成品 |
| 设置 | 合法键更新、未知键忽略、空怪兽池拒绝、刷新后仍存在 |
| 安全 | 未脱敏异常、任意管理写操作、CORS 和上传边界检查 |

## 6. 通过标准

- 所有已配置自动化检查退出码为 0。
- 没有测试连接开发/生产数据库的证据。
- 文档变更至少运行链接/敏感信息扫描和 `git diff --check`。
- 未运行的检查及原因必须如实记录，不能沿用历史交接文档中的通过结果。
