# 安全说明

## 1. 当前安全定位

Word Quest 当前只适合单机或受控家庭局域网。它没有可靠的身份认证与路由授权，不应直接暴露到互联网，也不应把“用户名为 Admin”视为安全边界。

## 2. 信任边界与敏感资产

| 边界/资产 | 风险 |
|---|---|
| 浏览器 → Backend | 调用者可伪造 `user_id`、用户名及管理写请求 |
| Backend → MySQL | 数据库凭据、儿童档案和学习记录 |
| Backend → AI service | 上传的绘本图片、提示词和生成内容 |
| AI service → CLI | `agy`/`codex` 登录资料、模型调用额度、CLI 输出 |
| Docker 宿主挂载 | 个人 `.gemini`/`.codex` 目录当前以读写方式进入容器 |
| WSL2/LAN 暴露 | 端口转发可能让同网段甚至更广网络访问无认证接口 |

敏感数据包括数据库密码、CLI Token/Cookie、代理凭据、儿童姓名/档案、上传图片和学习记录。不得写入文档、日志、Git 或 API 错误。

## 3. 当前控制

- SQL 大多通过参数占位符执行，动态分组筛选不直接拼接用户值。
- 图片限制为 JPEG/PNG/WebP，单次最多 10 张；后端 Multer 单文件限制 5 MB。
- Story/word 关联写入中的部分操作使用数据库事务。
- Compose 使用外部共享网络访问 MySQL，项目本身不管理数据库容器。
- AI 工具和模型通过配置白名单选择，不能把任意客户端字符串直接当作 shell 命令。
- iPad 语音开发环境使用 HTTPS 安全上下文。

## 4. 必须遵守的开发规则

- 所有管理写接口必须进行服务端输入校验；不能只依赖前端表单。
- 不得使用 `child_process` 的 shell 字符串拼接执行客户端提供的 CLI、模型、路径或提示词。
- CLI 临时文件使用独立随机目录，任务完成后清理；文件名不能决定宿主路径。
- 只挂载 CLI 运行所需的最小凭据，优先只读或专用服务账号。
- 数据库账号只授予 Word Quest 所需权限；开发、测试和生产凭据分离。
- CORS 只允许明确的本地来源；生产端口默认绑定回环地址或由受控反向代理保护。
- 错误响应使用稳定公开消息，原始异常仅写入受保护日志并进行秘密脱敏。
- 上传除 MIME 外还应验证实际文件签名、解码结果、像素/总字节上限和超时。
- 任何数据库清理、恢复、用户批量删除或凭据修改都需要明确目标和用户授权。

## 5. 尚未解决的高风险项

- 无身份认证、无服务端管理员授权，任意可达客户端可调用管理接口。
- Backend 和 AI service 允许所有来源 CORS；部分端口绑定所有接口。
- Compose 含硬编码数据库凭据、个人宿主路径和固定代理地址。
- CLI 凭据目录以读写挂载到 AI 容器。
- 多个接口把原始数据库/内部异常返回客户端；AI 解析失败也可能返回 CLI 错误细节。
- 数据库启动迁移失败只记录日志，应用仍可能继续提供不完整服务。

详细影响与临时规避见 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)。在这些问题解决前，必须把服务限制在可信主机/局域网并使用主机防火墙。

## 6. 安全验证

- 依赖与容器镜像漏洞扫描。
- API 未认证访问和越权测试，尤其是用户删除、金币、故事、分组和设置接口。
- SQL 注入、保留分组名、负数/极大数值和 JSON 体积边界测试。
- 图片伪装、解压炸弹、大像素、超时和恶意文件名测试。
- CLI 参数注入、提示词导致的非 JSON 输出、临时目录穿越及错误日志泄密测试。
- Git 中秘密扫描，包括 Compose、历史文档、`.env*`、SQL dump 和测试 fixture。
